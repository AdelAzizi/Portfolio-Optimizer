# مستندات نیازمندی‌ها - وب اپلیکیشن هوشمند بهینه‌سازی سبد سهام ایران

## مقدمه

این پروژه یک وب اپلیکیشن هوشمند برای بهینه‌سازی سبد سهام در بازار بورس ایران است. هدف نهایی، ارائه پیشنهادهای سرمایه‌گذاری داده‌محور و قابل فهم به کاربران با پروفایل‌های ریسک متفاوت (تهاجمی، متعادل، دفاعی) از طریق یک رابط کاربری جذاب و ساده است. 

سیستم شامل سه بخش اصلی است:
1. **خط لوله داده خودکار (بک‌اند)** - موتور تحلیل و کشف استراتژی
2. **خروجی نهایی (API Contract)** - فایل `final_results.json` به عنوان منبع حقیقت واحد
3. **رابط کاربری (فرانت‌اند)** - وب اپلیکیشن مدرن برای نمایش نتایج

سیستم به صورت خودکار بهترین استراتژی‌های سرمایه‌گذاری را بر اساس آخرین داده‌های بازار کشف، اعتبارسنجی و ارائه می‌کند.

## نیازمندی‌ها

### نیازمندی 1: ایجاد جهان سرمایه‌گذاری

**داستان کاربر:** به عنوان یک تحلیلگر، می‌خواهم سیستم بتواند از میان تمام سهام بورس، بهترین کاندیداها را شناسایی و فیلتر کند تا روی سهام باکیفیت تمرکز کنم.

#### معیارهای پذیرش
1. WHEN سیستم شروع شود THEN باید لیست کامل سهام بورس تهران را دریافت کند
2. WHEN فیلترینگ انجام شود THEN باید سهام با نقدینگی کافی و تاریخچه مناسب انتخاب شوند
3. IF سهامی معیارهای کیفی نداشته باشد THEN از جهان سرمایه‌گذاری حذف شود
4. WHEN جهان نهایی تشکیل شود THEN باید حدود 700 سهم برتر شامل باشد
5. WHEN فرآیند کامل شود THEN لیست نهایی باید برای مراحل بعدی ذخیره شود

### نیازمندی 2: جمع‌آوری داده‌های قیمتی و بنیادی

**داستان کاربر:** به عنوان یک تحلیلگر کمی، می‌خواهم سیستم بتواند داده‌های قیمتی و بنیادی سهام انتخاب شده را به صورت خودکار و قابل اعتماد جمع‌آوری کند.

#### معیارهای پذیرش
1. WHEN لیست سهام آماده شود THEN سیستم باید تاریخچه قیمت هر سهم را از tsetmc.com دانلود کند
2. WHEN داده‌های قیمتی دریافت شوند THEN باید تمیز شده و در فرمت استاندارد ذخیره شوند
3. WHEN داده‌های بنیادی مورد نیاز باشند THEN باید از منابع معتبر مانند Codal جمع‌آوری شوند
4. IF خطای دانلود رخ دهد THEN سیستم باید چندین بار تلاش کند
5. WHEN داده‌ها آماده شوند THEN باید در cache ذخیره شوند تا دسترسی سریع باشد

### نیازمندی 3: پردازش داده‌ها و محاسبه فاکتورهای مالی

**داستان کاربر:** به عنوان یک استراتژیست، می‌خواهم سیستم بتواند داده‌های خام را پردازش کرده و فاکتورهای مالی مختلف مانند momentum، volatility، و reversal را محاسبه کند.

#### معیارهای پذیرش
1. WHEN داده‌های خام آماده شوند THEN سیستم باید آنها را یکپارچه‌سازی و تمیز کند
2. WHEN پردازش انجام شود THEN فاکتورهای momentum 6 و 12 ماهه محاسبه شوند
3. WHEN محاسبات ادامه یابد THEN فاکتورهای volatility و reversal با دقت محاسبه شوند
4. IF داده‌های ناکافی وجود داشته باشد THEN سیستم باید خطای واضح نمایش دهد
5. WHEN فاکتورها آماده شوند THEN باید به صورت normalized و آماده تحلیل ذخیره شوند

### نیازمندی 4: مرحله اول - انتخاب و بک‌تست 300 استراتژی برتر (Strategy Tester)

**داستان کاربر:** به عنوان یک تحلیلگر استراتژی، می‌خواهم سیستم بتواند از فایل `data/strategy_test_results.csv` موجود، 300 استراتژی برتر را انتخاب کرده و آنها را با بک‌تست یک ساله در `src/strategy_tester.py` ارزیابی کند.

#### معیارهای پذیرش
1. WHEN فایل `data/strategy_test_results.csv` موجود باشد THEN سیستم باید 300 استراتژی با بالاترین Sharpe Ratio را انتخاب کند
2. WHEN استراتژی‌ها انتخاب شوند THEN باید بک‌تست یک ساله روی آنها در `strategy_tester.py` اجرا شود
3. IF کش 11 ساعته موجود باشد THEN از اجرای مجدد جلوگیری شود
4. WHEN بک‌تست کامل شود THEN 100 استراتژی برتر بر اساس Sharpe Ratio انتخاب شوند
5. WHEN نتایج آماده شوند THEN باید به `strategy_selector.py` ارسال شوند

### نیازمندی 5: مرحله دوم - دسته‌بندی بر اساس ریسک و انتخاب کاندیداها (Strategy Selector)

**داستان کاربر:** به عنوان یک مدیر ریسک، می‌خواهم سیستم در `src/strategy_selector.py` بتواند 100 استراتژی برتر را بر اساس سطح ریسک (Annualized Volatility) دسته‌بندی کرده و از هر دسته 5 کاندیدا انتخاب کند.

#### معیارهای پذیرش
1. WHEN 100 استراتژی برتر از `strategy_tester.py` دریافت شوند THEN باید بر اساس Annualized Volatility به سه گروه تقسیم شوند
2. WHEN دسته‌بندی انجام شود THEN 30% کم‌ریسک (دفاعی)، 40% متعادل، 30% پرریسک (تهاجمی) تعریف شوند
3. IF از هر دسته انتخاب شود THEN 5 استراتژی برتر هر گروه بر اساس Sharpe Ratio انتخاب شوند
4. WHEN انتخاب کامل شود THEN مجموعاً 15 کاندیدا (5 از هر دسته) تولید شوند
5. WHEN کاندیداها آماده شوند THEN باید به `validator.py` برای اعتبارسنجی نهایی ارسال شوند

### نیازمندی 6: مرحله سوم - اعتبارسنجی نهایی و تولید خروجی (Validator)

**داستان کاربر:** به عنوان یک مدیر محصول، می‌خواهم سیستم در `src/validator.py` بتواند 15 کاندیدا را با بک‌تست 5 ساله اعتبارسنجی کرده و بهترین استراتژی هر دسته را برای فرانت‌اند در `results/final_results.json` آماده کند.

#### معیارهای پذیرش
1. WHEN 15 کاندیدا از `strategy_selector.py` دریافت شوند THEN باید بک‌تست واقعی‌تر 5 ساله روی آنها اجرا شود
2. WHEN بک‌تست انجام شود THEN باید look-ahead bias جلوگیری شده و هزینه‌های معاملاتی لحاظ شوند
3. IF از هر دسته 5 تایی انتخاب شود THEN بهترین استراتژی بر اساس Sharpe Ratio انتخاب شود
4. WHEN 3 استراتژی نهایی انتخاب شوند THEN باید با تمام جزئیات در `results/final_results.json` ذخیره شوند
5. WHEN فایل نهایی تولید شود THEN باید شامل optimal_weights، performance_summary، backtest_data و transaction_analysis باشد

### نیازمندی 7: اجرای خودکار و زمان‌بندی

**داستان کاربر:** به عنوان یک مدیر سیستم، می‌خواهم پایپ‌لاین به صورت خودکار هر 12 ساعت یک بار اجرا شده و نتایج را در محلی قابل دسترس برای تیم فرانت‌اند قرار دهد تا وب‌اپ همیشه با داده‌های بروز تغذیه شود.

#### معیارهای پذیرش
1. WHEN سیستم راه‌اندازی شود THEN باید قابلیت اجرای خودکار هر 12 ساعت داشته باشد
2. WHEN پایپ‌لاین کامل شود THEN نتایج باید در محل مشخص شده برای API قرار گیرند
3. IF اجرای خودکار با خطا مواجه شود THEN سیستم باید تلاش مجدد کند
4. WHEN نتایج آماده شوند THEN باید در فرمت مناسب برای فرانت‌اند ذخیره شوند
5. WHEN زمان‌بندی فعال باشد THEN وضعیت اجرا باید قابل نظارت باشد

### نیازمندی 8: تولید خروجی استاندارد API

**داستان کاربر:** به عنوان یک توسعه‌دهنده فرانت‌اند، می‌خواهم بک‌اند یک فایل JSON استاندارد با ساختار مشخص تولید کند تا بتوانم وب‌اپ را بر اساس آن طراحی کنم.

#### معیارهای پذیرش
1. WHEN پایپ‌لاین کامل شود THEN باید فایل `final_results.json` با ساختار مشخص تولید شود
2. WHEN خروجی تولید شود THEN باید شامل سه پروفایل ریسک (تهاجمی، متعادل، دفاعی) باشد
3. IF هر پروفایل تعریف شود THEN باید شامل نام، آیکون، عملکرد، و وزن‌های بهینه باشد
4. WHEN داده‌های backtest آماده شوند THEN باید تاریخ‌ها و مقادیر استراتژی و benchmark شامل شوند
5. WHEN فایل نهایی ذخیره شود THEN باید در محل قابل دسترس برای فرانت‌اند قرار گیرد

### نیازمندی 9: مدیریت خطا و گزارش‌دهی پیشرفته

**داستان کاربر:** به عنوان یک کاربر سیستم، می‌خواهم در صورت بروز خطا، اطلاعات کافی دریافت کنم و سیستم بتواند خطاها را به صورت هوشمند مدیریت کند، خصوصاً در حالت اجرای خودکار.

#### معیارهای پذیرش
1. WHEN خطای اتصال شبکه رخ دهد THEN سیستم باید چندین بار با تأخیر تصاعدی تلاش کند
2. IF خطای غیرقابل بازیابی رخ دهد THEN سیستم باید اعضای تیم را مطلع کند
3. WHEN عملیات انجام شود THEN تمام مراحل با جزئیات کامل در log ثبت شوند
4. IF داده‌ای موجود نباشد THEN سیستم باید از منابع پشتیبان یا cache قدیمی استفاده کند
5. WHEN خطای حیاتی رخ دهد THEN سیستم باید notification (ایمیل/SMS) ارسال کند
6. WHEN سیستم کامل شود THEN گزارش جامع از عملکرد و وضعیت سلامت ارائه شود

### نیازمندی 10: سیستم کش هوشمند

**داستان کاربر:** به عنوان یک مدیر سیستم، می‌خواهم پایپ‌لاین از سیستم کش هوشمند استفاده کند تا از اجرای غیرضروری مراحل جلوگیری شده و عملکرد بهینه شود.

#### معیارهای پذیرش
1. WHEN فایل‌های پایپ‌لاین اجرا شوند THEN باید کش 11 ساعته برای اکثر مراحل اعمال شود
2. WHEN `full_market_fundamental_collector` اجرا شود THEN باید کش هفتگی برای آن اعمال شود
3. IF کش معتبر موجود باشد THEN از اجرای مجدد آن مرحله جلوگیری شود
4. WHEN کش منقضی شود THEN مرحله مربوطه باید مجدداً اجرا شود
5. WHEN تغییرات کوچک در سیستم رخ دهد THEN نباید کل پایپ‌لاین مجدداً اجرا شود

### نیازمندی 11: استقرار و اتوماسیون

**داستان کاربر:** به عنوان یک DevOps engineer، می‌خواهم سیستم بتواند به صورت خودکار در محیط ابری مستقر شده و بدون دخالت انسان کار کند.

#### معیارهای پذیرش
1. WHEN کد در GitHub push شود THEN باید GitHub Actions به صورت خودکار پایپ‌لاین را اجرا کند
2. WHEN پایپ‌لاین اجرا شود THEN باید در محیط Docker قابل اجرا باشد
3. IF استقرار انجام شود THEN باید فایل نهایی در Firebase Storage یا GitHub Pages قرار گیرد
4. WHEN زمان‌بندی تنظیم شود THEN باید هر 12 ساعت به صورت خودکار اجرا شود
5. WHEN مشکلی در استقرار رخ دهد THEN باید سیستم monitoring آن را تشخیص دهد
