# results/

## 1. Purpose of This Directory

This directory serves as the central repository for all outputs generated by the portfolio optimization pipeline, including final optimization results, detailed backtest data, performance summaries, transaction analyses, and various visual reports.

## 2. File Breakdown

### 📄 [`final_results.json`](results/final_results.json)

#### Purpose:

This JSON file stores the comprehensive results of the portfolio optimization and backtesting process for different investment strategies.

#### Key Components & Logic:

The file is structured to contain results for various portfolio strategies (e.g., "aggressive", "balanced", "defensive"). Each strategy entry includes:

- `optimal_weights`: A dictionary showing the optimal allocation (weights) for each stock in the portfolio.
- `performance_summary`: A summary of key performance metrics such as "Total Return", "Annualized Volatility", "Annualized Return", and "Sharpe Ratio".
- `backtest_data`: Contains arrays of historical `dates`, `strategy_values` (portfolio performance over time), and `benchmark_values` (benchmark performance over time) for comparative analysis.
- `transaction_analysis`: Details the rebalancing history, including `sold` and `bought` assets with their respective percentages at each rebalance `date`.

#### How to Use:

This file is an output artifact, not meant to be run directly. It is generated by the portfolio optimization and backtesting scripts (e.g., `optimizer.py`, `strategy_tester.py`) and can be consumed by reporting tools or for further analysis.

### 📁 [`backtest_results/`](results/backtest_results/)

#### Purpose:

This subdirectory stores detailed outputs specifically related to the backtesting process, including summary text files and generated images.

#### Key Components & Logic:

This directory typically contains:

- `backtest_summary.txt`: A text file summarizing the key performance metrics and findings from the backtest.
- `images/`: A nested directory holding various plots and charts generated during backtesting, such as `backtest_comparison.png`, `backtest_performance.png`, and other strategy-specific performance visualizations.

#### How to Use:

This directory is populated automatically by the backtesting components of the portfolio optimization pipeline. Its contents are for review and analysis of historical strategy performance.

### 📁 [`images/`](results/images/)

#### Purpose:

This subdirectory is dedicated to storing various graphical visualizations and plots generated throughout the portfolio optimization and analysis process.

#### Key Components & Logic:

This directory contains visual outputs such as:

- `correlation_heatmap.png`: A heatmap illustrating the correlation between different assets or factors.
- `efficient_frontier_*.png`: Plots showing the efficient frontier for different optimization scenarios (e.g., `efficient_frontier_comparison.png`, `efficient_frontier_optimizer.png`), visualizing optimal risk-return trade-offs.
- `multifactor_backtest_result.png`, `rolling_backtest_result.png`, `walk_forward_validation.png`: Specific plots related to backtest results and validation processes.

#### How to Use:

These images are generated by the analysis and visualization scripts within the project to provide an intuitive understanding of portfolio performance, optimization outcomes, and factor relationships. They are for visual inspection and reporting.

### 📁 [`reports/`](results/reports/)

#### Purpose:

This subdirectory is used to store generated textual reports that summarize the overall portfolio analysis and optimization outcomes.

#### Key Components & Logic:

This directory typically contains files like `portfolio_analysis_report_v3_YYYYMMDD_HHMMSS.txt`, which are timestamped reports detailing the results of a specific run of the portfolio optimization pipeline. These reports provide a human-readable summary of the process and its findings.

#### How to Use:

These reports are automatically generated at the conclusion of a full pipeline run, offering a concise overview of the portfolio's performance, composition, and other relevant metrics.

## 3. Dependencies & Interactions

The `results/` directory is primarily an output directory. Its contents are generated by various scripts within the `src/` directory, particularly those responsible for portfolio optimization (`optimizer.py`), strategy testing (`strategy_tester.py`), and data visualization. The `final_results.json` file is a key output that consolidates data from these processes. The images and reports within this directory are direct visualizations and summaries derived from the processed data and backtest outcomes. While this directory does not directly depend on other files for its _execution_, its _content_ is entirely dependent on the successful execution and data processing performed by other parts of the portfolio optimization project.

# نتایج/

## 1. هدف این دایرکتوری

این دایرکتوری به عنوان مخزن مرکزی برای تمامی خروجی‌های تولید شده توسط پایپ‌لاین بهینه‌سازی پورتفولیو عمل می‌کند، شامل نتایج نهایی بهینه‌سازی، داده‌های دقیق بک‌تست، خلاصه‌های عملکرد، تحلیل‌های تراکنش، و گزارش‌های بصری مختلف.

## 2. تفکیک فایل‌ها

### 📄 [`final_results.json`](results/final_results.json)

#### هدف:

این فایل JSON نتایج جامع فرآیند بهینه‌سازی پورتفولیو و بک‌تست را برای استراتژی‌های سرمایه‌گذاری مختلف ذخیره می‌کند.

#### اجزای کلیدی و منطق:

ساختار فایل به گونه‌ای است که نتایج استراتژی‌های مختلف پورتفولیو (مانند "تهاجمی"، "متعادل"، "تدافعی") را در بر می‌گیرد. هر ورودی استراتژی شامل:

- `optimal_weights`: دیکشنری حاوی تخصیص بهینه (وزن‌ها) برای هر سهم در پورتفولیو.
- `performance_summary`: خلاصه‌ای از معیارهای عملکرد کلیدی مانند "بازده کل"، "نوسان سالانه"، "بازده سالانه" و "نسبت شارپ".
- `backtest_data`: شامل آرایه‌هایی از `dates` (تاریخ‌ها)، `strategy_values` (عملکرد پورتفولیو در طول زمان) و `benchmark_values` (عملکرد بنچمارک در طول زمان) برای تحلیل مقایسه‌ای.
- `transaction_analysis`: جزئیات تاریخچه بازتراز کردن، شامل دارایی‌های `sold` (فروخته شده) و `bought` (خریداری شده) با درصدهای مربوطه در هر `date` (تاریخ) بازتراز.

#### نحوه استفاده:

این فایل یک خروجی است و مستقیماً اجرا نمی‌شود. توسط اسکریپت‌های بهینه‌سازی پورتفولیو و بک‌تست (مانند `optimizer.py`، `strategy_tester.py`) تولید می‌شود و می‌تواند توسط ابزارهای گزارش‌دهی یا برای تحلیل‌های بیشتر مورد استفاده قرار گیرد.

### 📁 [`backtest_results/`](results/backtest_results/)

#### هدف:

این زیردایرکتوری خروجی‌های دقیق مربوط به فرآیند بک‌تست را ذخیره می‌کند، شامل فایل‌های متنی خلاصه و تصاویر تولید شده.

#### اجزای کلیدی و منطق:

این دایرکتوری معمولاً شامل:

- `backtest_summary.txt`: یک فایل متنی که معیارهای عملکرد کلیدی و یافته‌های بک‌تست را خلاصه می‌کند.
- `images/`: یک دایرکتوری تو در تو که نمودارها و چارت‌های مختلف تولید شده در طول بک‌تست را نگهداری می‌کند، مانند `backtest_comparison.png`، `backtest_performance.png` و سایر تجسم‌های عملکردی خاص استراتژی.

#### نحوه استفاده:

این دایرکتوری به طور خودکار توسط اجزای بک‌تست پایپ‌لاین بهینه‌سازی پورتفولیو پر می‌شود. محتویات آن برای بررسی و تحلیل عملکرد استراتژی‌های تاریخی است.

### 📁 [`images/`](results/images/)

#### هدف:

این زیردایرکتوری به ذخیره‌سازی تجسم‌های گرافیکی و نمودارهای مختلف تولید شده در طول فرآیند بهینه‌سازی و تحلیل پورتفولیو اختصاص دارد.

#### اجزای کلیدی و منطق:

این دایرکتوری شامل خروجی‌های بصری مانند:

- `correlation_heatmap.png`: یک نقشه‌حرارتی که همبستگی بین دارایی‌ها یا فاکتورهای مختلف را نشان می‌دهد.
- `efficient_frontier_*.png`: نمودارهایی که مرز کارا را برای سناریوهای بهینه‌سازی مختلف (مانند `efficient_frontier_comparison.png`، `efficient_frontier_optimizer.png`) نشان می‌دهند و مبادلات بهینه ریسک-بازده را تجسم می‌کنند.
- `multifactor_backtest_result.png`، `rolling_backtest_result.png`، `walk_forward_validation.png`: نمودارهای خاص مربوط به نتایج بک‌تست و فرآیندهای اعتبارسنجی.

#### نحوه استفاده:

این تصاویر توسط اسکریپت‌های تحلیل و تجسم در پروژه تولید می‌شوند تا درک بصری از عملکرد پورتفولیو، نتایج بهینه‌سازی و روابط فاکتورها را فراهم کنند. آنها برای بازرسی بصری و گزارش‌دهی هستند.

### 📁 [`reports/`](results/reports/)

#### هدف:

این زیردایرکتوری برای ذخیره‌سازی گزارش‌های متنی تولید شده که نتایج کلی تحلیل و بهینه‌سازی پورتفولیو را خلاصه می‌کنند، استفاده می‌شود.

#### اجزای کلیدی و منطق:

این دایرکتوری معمولاً شامل فایل‌هایی مانند `portfolio_analysis_report_v3_YYYYMMDD_HHMMSS.txt` است که گزارش‌های دارای برچسب زمانی هستند و جزئیات نتایج یک اجرای خاص از پایپ‌لاین بهینه‌سازی پورتفولیو را ارائه می‌دهند. این گزارش‌ها خلاصه‌ای قابل خواندن برای انسان از فرآیند و یافته‌های آن را فراهم می‌کنند.

#### نحوه استفاده:

این گزارش‌ها به طور خودکار در پایان یک اجرای کامل پایپ‌لاین تولید می‌شوند و یک نمای کلی مختصر از عملکرد پورتفولیو، ترکیب آن و سایر معیارهای مرتبط را ارائه می‌دهند.

## 3. وابستگی‌ها و تعاملات

دایرکتوری `results/` در درجه اول یک دایرکتوری خروجی است. محتویات آن توسط اسکریپت‌های مختلف در دایرکتوری `src/`، به ویژه آنهایی که مسئول بهینه‌سازی پورتفولیو (`optimizer.py`)، تست استراتژی (`strategy_tester.py`) و تجسم داده‌ها هستند، تولید می‌شود. فایل `final_results.json` یک خروجی کلیدی است که داده‌ها را از این فرآیندها یکپارچه می‌کند. تصاویر و گزارش‌های موجود در این دایرکتوری، تجسم‌ها و خلاصه‌های مستقیمی هستند که از داده‌های پردازش شده و نتایج بک‌تست به دست آمده‌اند. در حالی که این دایرکتوری مستقیماً برای _اجرای_ خود به فایل‌های دیگر وابسته نیست، _محتوای_ آن کاملاً به اجرای موفق و پردازش داده‌ها توسط سایر بخش‌های پروژه بهینه‌سازی پورتفولیو وابسته است.
